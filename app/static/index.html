音频源

识别引擎
指定中文可避免把中文识别成英文。腾讯一句话识别不支持自动检测，「自动」时按中文处理。
腾讯云控制台 → 访问管理 → API 密钥管理。语音识别需开通「一句话识别」。
填兼容 /audio/transcriptions 的服务地址，可指向中转或自建服务。
识别时段
按容器本地时间（TZ 环境变量），跨午夜可设 22:00–06:00；起止相同表示全天。时段外会断开拉流，摄像头不再被拉取，进入时段自动重连（约 2 秒）；已有的识别积压会在时段外继续后台转完，不会等到第二天。顶部识别开关只影响识别，不影响拉流和播放。
VAD 静音检测
0 最灵敏（小声也会识别，噪声多），3 最严格（嘈杂环境更干净）。
低于该音量的声音不算语音。噪声大往上调（如 -35），说话轻就往下调（如 -55）。
一般保持 30 即可。
静音持续多久认为一句话结束。调小断句快，调大句子更完整。
低于此时长的声音会被忽略，可过滤咳嗽、开关门等短噪声。
一段音频里"真语音帧"的最低占比。噪声往往只有零星几帧被判为语音，调到 50% 以上能明显减少空识别；设 0 关闭此项。
开讲前补进片段的音频。VAD 判定有滞后，不补会吞掉字头；设 0 关闭。
切段时保留多少静音尾。整段 600ms 静音送进模型容易产生幻觉文本，裁短更干净也更快。
这些参数保存后立即生效，无需重启容器。
噪音结果过滤
识别结果（忽略标点、不分大小写）完全等于其中任一词时丢弃。已内置常见语气词与幻觉词，这里补现场特有的杂音词即可。
模型对纯噪声会"编"出文字（嗯、啊、四、Here.）。此开关只影响入库与推送，不影响拉流；关闭后记录全部原始结果。
识别队列
完整优先：语音段写入 ./data/pending.db，ASR 慢时后台按采集顺序慢慢补识别，容器重启不丢，入库时间仍是说话时刻。实时优先：只在内存排队，等太久就丢，保证低延迟。切换模式需重启容器。
超出后丢最旧的一段并记日志。保存即生效，无需重启。注意：上限只延缓溢出，服务端长期跟不上产出速度时积压仍会涨到上限。
待识别队列的磁盘硬上限，防止把 ./data 卷写满。保存即生效，无需重启；设置前确认 ./data 所在磁盘剩余空间足够。积压清空后会自动回收 pending.db 占用的空间。
完整优先模式下，采集间隔小于该秒数的相邻语音段合并成一次识别请求：摊薄每请求约 2 秒的固定开销，吞吐翻 2~3 倍，连续对话滞后明显下降，上下文变长断句也更准。0 = 关闭合并。保存即生效，无需重启。
合并后的单次识别请求最长包含多少秒音频，防止单请求过大拖慢单次推理。完整优先模式生效。
拉流与调试
网络 I/O 超时，同时作为「无音频数据」看门狗：超过该秒数没数据就断开重连，避免摄像头半开时静默卡死。拉不到流会按 5→10→20→40→60 秒退避。
仅「实时优先」模式生效：排队超过该秒数直接丢弃，不补识别几十秒前的话。设为 0 = 不限制。完整优先模式按队列条数/容量限制，不按等待时间丢。
开启后，被 VAD 或文本层丢弃的片段存到 ./data/audio/rejected/（WAV，最多保留 50 个）。回听可判断是噪声还是误杀，调完参数建议关掉。
